# InvestBest — Design Specification Document

**Version:** 0.1.0  
**Last updated:** March 2025

---

## 1. Executive Summary

InvestBest is an AI-powered quantitative research and trading platform that enables users to create, backtest, and manage algorithmic trading strategies. The system generates trading signals, supports paper trading via Alpaca, and delivers notifications through multiple channels.

---

## 2. Product Vision & Goals

### 2.1 Vision
Provide a unified platform for quantitative traders to research, validate, and deploy systematic trading strategies with minimal friction.

### 2.2 Goals
- **Research**: Backtest strategies on historical data with configurable parameters
- **Execution**: Paper-trade strategies via Alpaca (future: live trading)
- **Monitoring**: Track signals, positions, and portfolio performance
- **Alerts**: Receive notifications on signals and system events via email, Slack, or Telegram

## 4. Content & Functionality

### 4.1 Dashboard

**Purpose:** Central overview of portfolio status, recent activity, and system health.

**Content:**
- **Portfolio value** — Current paper trading portfolio value (placeholder)
- **Daily PnL** — Daily profit/loss (placeholder)
- **Active strategies** — Count of strategies with status `active`
- **Recent signals** — Last 10 signals (time, strategy, symbol, signal, confidence)
- **System status** — Configuration status for Polygon, Alpaca, FRED, OpenAI

**Functionality:**
- Auto-refresh metrics from API on load
- Links to Strategies, Signals, and System pages

---

### 4.2 Strategies

**Purpose:** Create, configure, and backtest trading strategies.

**Content:**
- **Strategy list** — Table of ID, name, status, module path, actions
- **Strategy form** — Name, description, module path, config (JSON)
- **Backtest panel** — Date range, run button, results (Sharpe, max drawdown, win rate, annual return)

**Functionality:**
- **Create:** POST new strategy with name, description, module_path, config_json
- **Edit:** PATCH existing strategy (name, description, status, config)
- **Backtest:** POST backtest request with strategy_id, start_date, end_date
- **Strategy statuses:** draft, backtesting, active, paused, retired

**Strategy configuration (JSON):**
- `lookback_days` — Momentum lookback period (default: 126)
- `top_pct` / `bottom_pct` — Percentile for long/short (default: 0.1)
- `top_n` — Number of top symbols to long (default: 1)

**Built-in strategy:** Cross-sectional momentum (`backend.strategies.momentum`)
- Ranks symbols by past return
- Longs top decile, shorts bottom decile
- Outputs signals: long, short, exit

---

### 4.3 Signals

**Purpose:** View trading signals generated by strategies.

**Content:**
- **Signals table** — Time, Strategy ID, Symbol, Signal (long/short/exit), Confidence

**Functionality:**
- List signals with optional filters (strategy_id, symbol)

**Data model:**
- `signal` — long, short, exit
- `confidence` — 0–1 score (optional)

---

### 4.4 Notifications

**Purpose:** Configure and view notification delivery.

**Content:**
- **Notification log** — List of sent notifications (channel, subject, body, status, created_at)
- **Send test** — Send a test notification to a channel

**Functionality:**
- List notifications (filter by channel, limit)
- Send test notification to email, Slack, or Telegram

**Channels:**

| Channel | Config | Purpose |
|---------|--------|---------|
| Email | SMTP host, port, user, password | Alert emails |
| Slack | Webhook URL | Slack channel alerts |
| Telegram | Bot token, chat ID | Telegram alerts |

---

### 4.5 System

**Purpose:** Monitor configuration and service health.

**Content:**
- **Status** — Polygon, Alpaca, FRED, OpenAI configured/missing
- **Services checklist** — Data providers, broker, AI, notifications

**Functionality:**
- Health check endpoint (`/health`) — Returns status for monitoring
- Services checklist — Used by UI to show configuration status

## 8. User Flows

### 8.1 Create and Backtest a Strategy

1. Navigate to **Strategies**
2. Click **New strategy**
3. Enter name, description, module path (e.g. `backend.strategies.momentum`)
4. Enter config JSON: `{"lookback_days": 126, "top_n": 1}`
5. Click **Save**
6. Click **Backtest** on the strategy row
7. Set start/end dates (optional)
8. Click **Run backtest**
9. View Sharpe, max drawdown, win rate, annual return

### 8.2 Activate a Strategy (Future)

1. Backtest strategy and review results
2. Update status to `active`
3. System will generate signals and execute trades (paper trading)

### 8.3 Receive Notifications

1. Configure SMTP/Slack/Telegram in `.env`
2. Navigate to **Notifications**
3. Click **Send test** to verify channel
4. When strategy generates signals, notifications are sent (future)

## 9. Backtest Logic

### 9.1 Data Flow

1. **BacktestService.run()** receives strategy, start_date, end_date
2. Loads prices from DB or generates synthetic data (SPY, QQQ, IWM)
3. Dispatches to strategy module (e.g. momentum)
4. Strategy returns daily returns series
5. Computes metrics: Sharpe, max drawdown, win rate, annual return

### 9.2 Momentum Strategy Logic

- Pivot prices by symbol
- Compute momentum: `price[t-1] / price[t-lookback-1] - 1`
- Rank symbols by momentum
- Long top N, short bottom N
- Strategy return = (long returns - short returns) / N

### 9.3 Metrics

- **Sharpe ratio:** Annualized excess return / volatility (√252)
- **Max drawdown:** Largest peak-to-trough decline
- **Win rate:** Fraction of days with positive return
- **Annual return:** Geometric annualized return

### B. Glossary

- **Signal:** A trading recommendation (long, short, exit) for a symbol
- **Backtest:** Simulated historical performance of a strategy
- **Paper trading:** Simulated execution without real money
- **Strategy:** A rule-based or algorithmic system that generates signals
